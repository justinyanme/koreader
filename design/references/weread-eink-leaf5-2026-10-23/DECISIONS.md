# 待定项裁决（2026-10-23）

对 [REQUIREMENTS.md](REQUIREMENTS.md) 里全部 [待定] 条目的裁决，写 spec 和拆 ticket 时以此为准。总原则：

- 交互和视觉一律按微信读书实机来；和现有 DESIGN.md、CONTEXT.md、design/demo 冲突时，以实机为准，并在同一批改动里更新文档。
- 依赖微信账号、云端、社区、书城的功能不做，也不做假按钮。
- KOReader 有、微信读书没有的能力不删，挪到次级位置。
- 需要新原生能力（Java 桥接、C++ 引擎钩子、重新打 APK）的功能本轮不做，留给 owner 决定。

## 本轮做

| 条目 | 裁决 |
| --- | --- |
| A10 底部导航、筛选、排序 | 书架页照抄微信读书：顶部搜索框，标题行“书架”加右侧“导入”“选择”，封面网格，底部左侧是三个纯图标标签，右侧是连体翻页胶囊。三个标签对应微信读书的“发现/书架/我”，我们用**书源/书架/我**（书源用指南针图标）。原来的“文件”标签挪进“导入”页和“我”页。状态筛选不再用一排 chips，改为点标题弹出菜单：全部、在读、未读、读完、搁置；标题显示当前筛选，比如“在读 ▾”，选“全部”时只显示“书架”。排序移到 设置 → 书架，默认最近阅读。本地书名前不加“已下载”的勾，因为书架上的书全在本地；勾只在书源里用。封面右上角的“读完”角标照抄。 |
| A05 导入 | “导入”打开一个全屏说明页，版式照抄微信读书的导入页：分段说明和底部圆形 × 关闭。内容换成 KOReader 的真实途径：浏览设备文件（进入文件页）、从书源下载（进入书源）、从电脑传书（Calibre 无线连接或 USB 拷进主目录，写明主目录路径）。 |
| A08 选择模式 | 照抄微信读书的选择模式：标题、空圈和实心勾、“已选择 N 本书籍”、全选（选中整个书架，不只当前页）、取消全选、右上“取消”。底部动作换成本地动作：**移出书架**（隐藏，不删文件，要确认）和**标记为**（读完、在读、搁置）。没有微信的下载、私密。 |
| A09 首页搜索 | 照抄独立搜索页：搜索框、搜索历史和“清空”，结果标题写“在书架中搜索：xx”。只搜本地书架的书名和作者，没有书城结果和推荐词。替换现在的原地过滤。 |
| B04 唤出工具栏 | 上滑唤出上下工具栏，点中间也能唤出（保留）。工具栏打开时点正文空白处收起，不翻页。 |
| B05 上滑提示 | 打开书时，底部中间显示灰色“↑ 上滑显示工具栏”，约 1 分钟后或第一次唤出工具栏后消失，翻页不重新出现，下次打开书再出现。 |
| C03 / C05 / T09 顶栏和“更多” | 顶栏图标靠右，从左到右是 **书签、书架状态、更多**，沿用微信读书的相对顺序，以后加繁简、手写时插在左边。书架状态对应微信的书架图标：书在书架上时显示带勾的图标，点击后出确认层“移出书架”（隐藏）；不在书架上时点击加回书架。“更多”占微信“下载状态”的位置，打开底部列表：亮度与色温、书籍详情（含个人评分和书评）、导出笔记、点击区域、阅读统计、设置、全部设置（原版）（“设置”是 #41 review 时补的：阅读中从这里进新版设置，按书生效的行可用）。“刷新与残影”不放这里，留在 设置 → 屏幕。底栏是 **返回 ｜ 目录 · 笔记 · 进度 · 字体**，返回后面有一条细竖线；“听”位置空缺，不放占位。 |
| C04 面板打开时工具栏保持可见 | 面板夹在正文和底栏之间，底栏始终保留。顶栏按实机：打开进度面板（以及亮度、更多）时保留，打开字体面板时隐藏（[02-typography/01-font-panel.png](02-typography/01-font-panel.png) 没有顶栏，[03-progress/01-progress-panel.png](03-progress/01-progress-panel.png) 有顶栏；此前写的“上下工具栏都保留”不准确，已更正）。这是结构性改动。 |
| D07 字体清单 | 主面板的字体卡片网格显示 KOReader 能用的字体：自带字体、用户 fonts 文件夹、Android 系统字体。每张卡片用该字体本身渲染名字，最后一格是“查看更多 ›”。“系统字体”指设备的系统中文字体，找不到时用自带的 Noto Sans CJK。“查看更多”打开全屏字体页，分类换成 **全部 / 中文 / 西文**（按字体是否覆盖中文字符判断），每类显示数量。不打包任何商业字体。 |
| E05 返回原进度 | 用进度条跳转后，正文上方出现描边胶囊“‹ 返回原进度”，点击回到第一次跳转前的位置，并收起工具栏和面板。连续多次拖动不覆盖最早的返回点。进度轨道上画一个灰点，标出原位置，灰点本身不可点。 |
| E06 进度面板的数字 | 三列分别是：当前位置百分比和“约 N 小时后读完”（用统计插件里本书的平均每页耗时乘以剩余页数，没有统计数据时不显示这一行）、本书累计阅读时长、笔记条数（划线、想法、书签之和）。点笔记那一列打开笔记页。 |
| F03 自动翻页速度 | 档位 1.0 / 1.5 / 2.0 / 3.0 / 4.0 对应每页 60 / 40 / 30 / 20 / 15 秒，接到 autoturn 插件。 |
| F04 划线导读 | 做，排最后、低优先级。自动翻页时，在当前行下方画一条导读线，按每页间隔均分到各行逐行下移，用快速刷新只刷线所在的小块。只支持流式书。 |
| J03 私密 | 不做私密开关。想法详情里可以保留静态的“仅自己可见”，本地确实只有自己可见。编辑器的提交按钮叫“保存”，不叫“发表”。 |
| J05 想法的生命周期 | 想法存成一条带 note 的 annotation，创建时写入 `origin = "note"`。删除想法时：如果这条是用“写想法”直接创建的，整条删掉；如果是先划线后加的想法，只清掉想法、保留划线。只有想法、没有显式划线的条目，在正文里画想法标记，不画直线。 |
| K07 划线样式 | 新划线默认直线，和微信一致。气泡里去掉样式选择行。旧的马克笔、波浪线照常显示。样式选择移到 设置 → 阅读 → 划线样式，复用上游的 `highlight_drawing_style`；没有显式保存过的值才改成直线默认。新写一个 ADR 取代 ADR-0003。 |
| K02 / L07 选词和查词 | 选词浮层照抄微信读书：白底、黑描边、有三角指向、上图标下文字。动作依次是 划线、查询（中文）或翻译（英文）、写想法、复制。不做“听当前”，去掉现在的“搜索”。查词页照抄微信的卡片堆：每本词典一张释义卡，卡片标注词典名，不用 chips；“百科”卡显示维基百科摘要（L05：用维基百科代替搜狗百科），点 › 打开完整条目。微信“全书繁转简”那张居中操作卡，换成“加入生词本”；“去书城搜索”那一行换成“在本书中搜索”。英文翻译优先查本地词典，多词选区再走在线翻译，并标明需要联网。 |
| N04 脚注 | 没有实机样本。保留 KOReader 的脚注弹层，只把视觉换成 DESIGN token 里的白卡片、1px 描边、圆角，低优先级。 |
| Q03 读完的第 N 本 | N 是本地标记为读完的书的总数（不限年份），按标记读完的时间排序，算上本书。只在本书状态为读完时显示。 |
| R05 界面字号 | 做。设置 → 阅读偏好里加“字体大小”，有 5 档：小、默认、大、较大、特大，对应缩放 0.9 / 1.0 / 1.1 / 1.2 / 1.35。只作用于新界面的文字层级，不影响正文，不改 DPI。 |
| T05 刷新验收 | 每张 ticket 的验收里都要在 Leaf5 上实机验证：把改过的 Lua 推到 dev overlay，重启 KOReader，截图和微信读书参考图对照。刷新规则沿用 #1：面板和工具栏用界面刷新，只刷对应区域；气泡和提示用快速刷新；只有打开书、回书架、切夜间模式允许全刷。 |
| T06 术语 | 改用微信的模型：**笔记**包括划线、想法和书签。笔记是一个全屏的笔记页，有书签时才出现“仅显示书签 / 显示全部”筛选。目录也改成全屏的目录页，代替目录抽屉。同步更新 CONTEXT.md：目录抽屉改为目录页，新增笔记页；想法放宽为“附在一段文字上的文字”。DESIGN.md 里的黑气泡、四格底栏、三档排版、侧抽屉一起改。 |
| T07 文件和书源 | 都保留。书源是底部第一个标签，文件从“导入”页和“我”页进入。书源的完整需求沿用 #24 和 #27。 |
| T08 “我”页 | 照抄微信：第一行是大号名字，第二行是“累计阅读 X 小时 Y 分钟”，第三行是“本周阅读 … ｜ 连续 N 天”，下面是带圆形图标、副标题和 › 的列表行。名字是设置里的昵称，默认取 KOSync 用户名，没有就用设备型号，点击可以改。点统计区打开 KOReader 的阅读统计，原来的周柱状图去掉。列表依次是：笔记（全部书）、生词本、文件、同步与传书、设置、版本更新（KOReader OTA，副标题显示当前版本）。 |
| O04 阅读中下载全部内容 | 不适用。本地文件本来就是完整的，不做。 |

## 本轮不做，留给 owner

| 条目 | 原因 |
| --- | --- |
| M01、M03–M09 听书（入口、定时关闭、语速、分集、播放和跳转、拖动、返回原文、迷你播放器） | KOReader 没有 TTS 和音频会话。要在 Android 启动器里加 Java 层的 TextToSpeech 桥接，还要重新打 APK；Kindle 没有对应能力。 |
| P01–P05 手写 | 没有笔迹采集、存储、重排锚定和低延迟墨迹。Boox 的笔延迟优化要用厂商 SDK。 |
| O01 繁简转换 | 渲染时转换要在 crengine 里加 C++ 钩子。另一条路是用 Lua 加字表生成一份“简体副本”新文件，不用改引擎，但要 owner 决定是否接受副本这种形式。 |
| N03 图片划线和写想法 | annotation 只支持文字范围，插图需要稳定锚点和新的数据模型，收益低。 |

## 微信读书独有，不做

A06、A11、J06、L06、M02、O05、Q05、S01–S08。
